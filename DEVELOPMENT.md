# Заметки для разработки

Пользовательская документация — в [`README.md`](README.md). Здесь то, что
нужно тому, кто правит код.

## Принципы

- **Боевой TUI.** Приложением пользуются каждый день: не менять
  поведение без объявления. Протокол и сборщик не трогаем: клиент только
  читает.
- **Минимализм.** Ничего «с запасом». Новый общий компонент (график,
  баннер, цифры) сначала пробуется здесь, а в `dtui-kit` попадает только
  после боя; здесь компоненты кита лишь используются.
- **Стиль через YAML, условное через Go.** Вид (шрифт, цвет, отступ,
  порог ширины, статические подписи) — в раскладке. Всё, что зависит от
  данных или состояния (например, цвет статуса подключения), остаётся в
  Go: приложение отдаёт движку уже готовое значение.
- **Бюджет движка `internal/dtui`**: строка, колонка, ширина (% или
  клетки), выравнивание. Если нужен новый вид контейнера или движок
  заметно растёт, остановиться и пересмотреть подход, а не растить язык.

## Грабли Charm v2

- `Width`/`Height` стиля с рамкой **включают рамку** (в v1 нет): никаких
  ручных `width-2`/`height-2` для блоков с рамкой.
- `bubbles/table`: обязателен `SetWidth`, иначе строки данных не
  рисуются (виден только заголовок). `SetHeight` уже учитывает
  заголовок. `columnBorderOverhead = 10` (4 колонки × 2 паддинга +
  2 рамки): при 6 таблица была шире рамки, и правая панель выезжала за
  край терминала.
- `View() tea.View`, `v.AltScreen = true` (опции `tea.WithAltScreen()`
  нет); клавиши — `tea.KeyPressMsg`; `lipgloss.Color` — функция;
  профилей цвета нет, стили детерминированы.
- `lipgloss.JoinVertical` добивает короткие строки пробелами и
  **маскирует** разъезд рамок: строки тела проверяй через
  `strings.TrimRight` (так сделан `TestView_BodyLinesMatchTerminalWidth`).
  `TestView_ShowsSymbolRowsAfterStatus` защищает от пустой таблицы.
- Ширину считай только через `lipgloss.Width`, не `len([]rune)`.
- `go-figure` на неизвестном шрифте вызывает `log.Fatal`: используй
  `banner.Fonts()` / `banner.IsKnownFont` кита (движок проверяет `font`
  при разборе YAML).
- `lipgloss.PlaceHorizontal` выравнивает **каждую строку отдельно**:
  блок сначала приведи к прямоугольнику (в движке это `rect()`), иначе
  FIGlet искажается.
- Не пытайся подогнать зазор «пробелом в label»: окрашенный пробел,
  отделённый от соседей ANSI-последовательностью, переносится в lipgloss
  иначе, чем цельная строка (хвостовые пробелы остаются, рамка выходит
  за терминал на 1–2 колонки). Текст рядом со значением — `suffix`/`label`
  одним куском.
- Цвета выключены в тестах, поэтому ошибки ширины, видимые только с
  цветом, тесты не ловят. Для рефакторингов сравнивай вывод старой и
  новой версии по символу, цвету и жирности на всех ширинах (так
  доказано, что YAML-шапка идентична прежней Go-шапке, а YAML-подвал —
  прежнему Go-подвалу на ширинах 20–260). Сравнивай по ячейкам (символ,
  цвет, жирность), а не побайтно: ANSI-последовательности могут быть
  разбиты иначе при том же виде. Цвет пустых ячеек (пробелов) не виден и
  не в счёт.

## Окружение

- Go версии из `go.mod`. Если локальный Go старше, помогает
  `export GOTOOLCHAIN=go1.27.1 GOPROXY=https://goproxy.cn,direct`:
  без этого `go get` тянет не те версии или падает по
  `TLS handshake timeout`. `GOSUMDB=off` ломает скачивание тулчейна.
- Сервера сборщика для проверки не нужно: тесты работают на подставных
  данных (`newTestModel`, `statusMsg`).
- Проверка перед коммитом:
  `go mod tidy && gofmt -l . && go vet ./... && go test ./... -race`,
  затем сборка и взгляд на экран.

## Зависимость от dtui-kit

Версия кита указана в `go.mod`. Из кита используются `theme`,
`sparkbar`, `banner` и `digits` (часы шапки).
Публичный API `theme` и `sparkbar` без плана миграции менять нельзя: у
них есть другие потребители. Чего не хватает киту, оформляй запросом
его автору (формат запроса описан в чате проекта).

## Проверка раскладки

`-check-layout` (см. README) гоняет зоны по диапазону ширин через
`Zone.Fit` движка: «нужно» против «есть». Диапазон и допущения (10-значный
счётчик) — константы в `internal/ui/check.go`; тест
`TestRenderHeader_NoWrapAndExactWidthAcrossWidths` использует те же.
Добавляя зону на движок, добавь её в `checkSamples()` с реалистичными
данными.

## Что дальше

1. Перенести тело (таблица + правая панель) на движок YAML: колонки по
   процентам, данные таблицы, графики-компоненты. Подвал уже на движке;
   цвет статуса остаётся в Go (зависит от состояния), раскладка и текст
   подсказки в YAML. Этап сложнее подвала: перед началом сверить с
   бюджетом движка (сейчас ~480 строк без тестов при ориентире ~300).
2. Остальные свойства из `ARCHITECTURE.md` кита: реализован только
   `margin-top`; `margin`/`padding` целиком — по мере нужды.
3. Зоны `leftbar` и `cmdline` появятся, когда понадобятся; горячая
   перезагрузка `layout.yaml` не сделана.
4. Когда раскладку захочет второй проект (`dtrader-tui-6`), вынести
   `internal/dtui` в отдельный проект `dtui` (перенос папки).
