# Заметки для разработки

Пользовательская документация — в [`README.md`](README.md). Здесь то, что
нужно тому, кто правит код.

## Принципы

- **Боевой TUI.** Приложением пользуются каждый день: не менять
  поведение без объявления. Протокол и сборщик не трогаем: клиент только
  читает.
- **Минимализм.** Ничего «с запасом». Новый общий компонент (график,
  баннер, цифры) сначала пробуется здесь, а в `dtui-kit` попадает только
  после боя; здесь компоненты кита лишь используются.
- **Стиль через YAML, условное через Go.** Вид (шрифт, цвет, отступ,
  порог ширины, статические подписи) — в раскладке. Всё, что зависит от
  данных или состояния (например, цвет статуса подключения), остаётся в
  Go: приложение отдаёт движку уже готовое значение.
- **Бюджет движка `internal/dtui`**: строка, колонка, ширина (% или
  клетки), выравнивание. Если нужен новый вид контейнера или движок
  заметно растёт, остановиться и пересмотреть подход, а не растить язык.

## Грабли Charm v2

- `Width`/`Height` стиля с рамкой **включают рамку** (в v1 нет): никаких
  ручных `width-2`/`height-2` для блоков с рамкой.
- `bubbles/table`: обязателен `SetWidth`, иначе строки данных не
  рисуются (виден только заголовок). `SetHeight` уже учитывает
  заголовок. `columnBorderOverhead = 10` (4 колонки × 2 паддинга +
  2 рамки): при 6 таблица была шире рамки, и правая панель выезжала за
  край терминала.
- `View() tea.View`, `v.AltScreen = true` (опции `tea.WithAltScreen()`
  нет); клавиши — `tea.KeyPressMsg`; `lipgloss.Color` — функция;
  профилей цвета нет, стили детерминированы.
- `lipgloss.JoinVertical` добивает короткие строки пробелами и
  **маскирует** разъезд рамок: строки тела проверяй через
  `strings.TrimRight` (так сделан `TestView_BodyLinesMatchTerminalWidth`).
  `TestView_ShowsSymbolRowsAfterStatus` защищает от пустой таблицы.
- Ширину считай только через `lipgloss.Width`, не `len([]rune)`.
- `go-figure` на неизвестном шрифте вызывает `log.Fatal`: используй
  `banner.Fonts()` / `banner.IsKnownFont` кита (движок проверяет `font`
  при разборе YAML).
- `lipgloss.PlaceHorizontal` выравнивает **каждую строку отдельно**:
  блок сначала приведи к прямоугольнику (в движке это `rect()`), иначе
  FIGlet искажается.
- `Width(width)` у панели с рамкой и `Padding(1,1)` оставляет содержимому
  `width-4`, а не `width-2`: на ширине графика правой панели это сказалось
  при пропорции 65/35 (узкая панель, график переносился; теперь снова 50/50, но ширина `width-4` по-прежнему нужна). Тест
  `TestRenderRightbar_ExactSizeOnNarrowPanel` держит ширину и высоту ровно.
- Не пытайся подогнать зазор «пробелом в label»: окрашенный пробел,
  отделённый от соседей ANSI-последовательностью, переносится в lipgloss
  иначе, чем цельная строка (хвостовые пробелы остаются, рамка выходит
  за терминал на 1–2 колонки). Текст рядом со значением — `suffix`/`label`
  одним куском.
- Цвета выключены в тестах, поэтому ошибки ширины, видимые только с
  цветом, тесты не ловят. Для рефакторингов сравнивай вывод старой и
  новой версии по символу, цвету и жирности на всех ширинах (так
  доказано, что YAML-шапка идентична прежней Go-шапке, а YAML-подвал —
  прежнему Go-подвалу на ширинах 20–260). Сравнивай по ячейкам (символ,
  цвет, жирность), а не побайтно: ANSI-последовательности могут быть
  разбиты иначе при том же виде. Цвет пустых ячеек (пробелов) не виден и
  не в счёт.

## Окружение

- Go версии из `go.mod`. Если локальный Go старше, помогает
  `export GOTOOLCHAIN=go1.27.1 GOPROXY=https://goproxy.cn,direct`:
  без этого `go get` тянет не те версии или падает по
  `TLS handshake timeout`. `GOSUMDB=off` ломает скачивание тулчейна.
- Сервера сборщика для проверки не нужно: тесты работают на подставных
  данных (`newTestModel`, `statusMsg`).
- Проверка перед коммитом:
  `go mod tidy && gofmt -l . && go vet ./... && go test ./... -race`,
  затем сборка и взгляд на экран.

## Зависимость от dtui-kit

Версия кита указана в `go.mod`. Из кита используются `theme`,
`sparkbar`, `banner` и `digits` (часы шапки).
Публичный API `theme` и `sparkbar` без плана миграции менять нельзя: у
них есть другие потребители. Чего не хватает киту, оформляй запросом
его автору (формат запроса описан в чате проекта).

## Проверка раскладки

`-check-layout` (см. README) гоняет зоны по диапазону ширин через
`Zone.Fit` движка: «нужно» против «есть». Диапазон и допущения (10-значный
счётчик) — константы в `internal/ui/check.go`; тест
`TestRenderHeader_NoWrapAndExactWidthAcrossWidths` использует те же.
Добавляя зону на движок, добавь её в `checkSamples()` с реалистичными
данными.

## Решение: тело остаётся в Go

Тело (таблица символов + правая панель CPU/RAM/DISK) на движок YAML
**не переносим**. Причины: оно требует нового вида контейнера (строка с
ширинами в процентах, зона на всю свободную высоту, реестр Go-компонентов;
оценка +80–120 строк движка при ~480 сейчас и ориентире ~300), а выгоды
(пропорция 60/40, смена панелей местами, скрытие панели на узком
терминале) пока никому не нужны: «добавляем только после боя». Вся
хрупкая часть (колонки таблицы, высота, рамки) всё равно осталась бы в
Go.

Вернуться к вопросу, когда появится конкретное желание, например:
изменить пропорцию, поменять панели местами, скрыть правую панель на
узком терминале. Набросок схемы:

```yaml
  - zone: body
    split:
      - { component: symbols-table,  width: 50% }
      - { component: system-metrics, width: 50%, show-from: 120 }
```

Тогда вместе с движком расширить `-check-layout` (сумма ширин панелей).

## Таблица символов: крупные тикеры (по умолчанию)

`-ticker-font` (по умолчанию `banner3-mini`, см. `internal/ui/symbols.go`).
`bubbles/table` строго однострочный, а FIGlet-тикер занимает 3–7 строк,
поэтому левая панель рисуется своим рендером (высокие строки, выбранная
строка и прокрутка воспроизведены вручную). Прежняя таблица не удалена:
она включается значением `-ticker-font off`, а модель `ui.Model` сама по
себе её и рисует (крупные тикеры включает `main.go`).

Строка символа: тикер (`tickerOf`: `BTC` из `BTC_USDT`) · возраст последней
записи тем же шрифтом (`formatAge`: `0.4s`, `12s`, `5m`, `2h`, `--`; в
`banner3` нет кириллицы, поэтому без слова «назад») · кружок (`symbolDot`):
зелёный пульсирующий, ярко-красный (запись застряла или связь потеряна,
признак связи: `lastErr != nil`, он снимается первым успешным статусом),
серый пустой (идёт первое подключение, данных и ошибки ещё нет). Заголовков и колонки «Снапшотов» нет:
общий счётчик остаётся в шапке.

Цену монеты в таблице **не показываем**: решение владельца (достаточно видеть,
что сборщик активен и пишет снапшоты). Пробовали два пути и оба закрыли: цена
из статуса сборщика (нужна правка боевого сборщика, отказались как слишком
рискованную) и цена напрямую с публичного REST Gate.io (отказались как
лишнюю). Следов в коде нет. Если когда-нибудь понадобится: в снапшоте сборщика
сделок нет, только стакан, «цена» это лучшие бид и аск (первые уровни
`bids`/`asks`), а клиент ничего о файлах сборщика не знает.

Правая панель (`rightbar.go`): три секции CPU, RAM, DISK по две строки: имя
крупным шрифтом таблицы (`m.tickerFont`) и строка «значение + график».
Графики всех секций начинаются с одного столбца (колонка значения шириной 6).
Если крупные имена не помещаются по ширине или все секции по высоте
(для `banner3-mini` нужно 14 строк содержимого, то есть около 30 строк
терминала), имена становятся обычным текстом; лишние нижние строки
обрезаются, чтобы панель не вылезала за рамку. Пропорция таблицы и панели:
`contentPercent = 50`.

Пульс (`pulseColor`): яркость зелёного по косинусу с периодом 2 секунды от
25% до 100% цвета `theme.ColorOK`, время берётся из `nowFn` (в тестах
подменяется). Тик приложения 500 мс даёт четыре ступени за период; если
захочется плавнее, это тик в `tickCmd` (он же двигает двоеточие часов).

Состояние символа (`symView`) считается в одном месте и для крупных тикеров,
и для прежней таблицы (`buildRows`); при рефакторинге строки старой
таблицы сверены с версией до него: расхождений нет.

Шрифты (`banner3-mini`, `banner3-compact`) приехали из кита `v0.5.0`;
локальные прототипы удалены (перед удалением вывод кита сверен с ними
побайтно на 100 случаях). Известные огрехи шрифтов (владелец — кит): в
`banner3-mini` штрих в 2 знака иногда ложится на границу ячеек (`▐▌`), в
`banner3-compact` у `C`, `S`, `G` «язычок» в соседней строке. По ответу
двойника кит разобрал причины и пока не правит (в mini чинится подгонкой
самого рисунка, в compact сдвиг пар строк ухудшает `B` и `T`); в документах
кита это не записано.

План: заголовки шапки через `banner`, затем удалить `bubbles/table` и режим
`off`, когда прежняя таблица точно не понадобится.
