# dtrader-history-tui

Консольный (TUI) монитор сборщика
[`dtrader-history`](https://github.com/Dmitriy-495/dtrader-history)
(`collector`). Это не торговый инструмент, а наблюдение: показывает,
что сборщик жив, пишет ли он данные по каждому символу и как себя
чувствует VPS.

Клиент ничего не знает о файлах и процессах сборщика: он только читает
то, что сборщик отдаёт по сети (статус по WebSocket, метрики VPS по
HTTP). Запускается на любой машине, SSH-доступ к VPS не нужен. Протокол
и сам сборщик клиент не меняет.

Переписан с Python (`textual`) на Go (`bubbletea`): один
самодостаточный бинарник вместо venv и интерпретатора. Палитра, графики
и баннеры берутся из общей библиотеки
[`dtui-kit`](https://github.com/Dmitriy-495/dtui-kit).

## Что на экране

```
┌────────────────────────────────────────────────────────────────────┐
│ шапка: логотип dtrader · часы UTC · счётчик снапшотов              │
├───────────────────────────────┬────────────────────────────────────┤
│ таблица символов (50% ширины) │ CPU / RAM / DISK VPS (50% ширины)  │
├───────────────────────────────┴────────────────────────────────────┤
│ подвал: соединение · аптайм сборщика · q — выход                   │
└────────────────────────────────────────────────────────────────────┘
```

- **Шапка.** FIGlet-логотип `dtrader` (на широком терминале рядом
  подпись `history`), справа крупные семисегментные часы UTC («ЧЧ:ММ», двоеточие мигает
  раз в секунду) и строка «снапшотов всего: N» (сумма по всем символам). На узком терминале шапка
  переходит на однострочный вид. Внешний вид задаётся YAML-файлом, см.
  [«Раскладка»](#раскладка-шапка-и-подвал).
- **Таблица символов.** По строке на каждый `-symbol`: количество
  снапшотов с запуска сборщика, возраст последней записи и статус:
  «работает», «ЗАСТРЯЛ?» (больше 5 секунд без новых данных) или «нет
  данных» (символ не пришёл в статусе). Возраст пересчитывается локально
  дважды в секунду, поэтому цифра не замирает между push-сообщениями.
- **Правая панель.** CPU, RAM и DISK VPS: текущее значение и график
  последних 40 замеров (блоки `▁▂▃▄▅▆▇█`). Цвет графика меняется на 70 %
  (предупреждение) и на 90 % (критично). Если `sysagent` недоступен,
  вместо графиков показывается причина; таблица от этого не страдает:
  это два независимых источника.
- **Подвал.** Состояние соединения со сборщиком («Подключение...»,
  «подключено · аптайм сборщика N с» или ошибка с переподключением) и
  подсказка `q — выход`. Подвал тоже описан в YAML: его вид и текст
  подсказки меняются без пересборки.

## Установка

```bash
go build -o tui-client .
```

Нужен Go версии, указанной в `go.mod`.

## Использование

```bash
./tui-client -host <IP-VPS-сборщика> \
  -symbol BTC_USDT -symbol SOL_USDT -symbol AVAX_USDT
```

Флаги:

| Флаг        | Обязателен | По умолчанию | Описание                                                                 |
|-------------|------------|--------------|--------------------------------------------------------------------------|
| `-host`     | да         | —            | IP или домен VPS, где крутится сборщик                                   |
| `-port`     | нет        | `8765`       | Порт статус-сервера сборщика (WebSocket)                                 |
| `-sys-port` | нет        | `8766`       | Порт `sysagent` (метрики CPU/RAM/DISK VPS, HTTP)                         |
| `-symbol`   | да (1+)    | —            | Символ для строки таблицы; указывается многократно                       |
| `-layout`   | нет        | —            | Путь к YAML-раскладке; описанные в ней зоны заменяют встроенные, без пересборки |
| `-check-layout` | нет    | —            | Проверить раскладку (встроенную или из `-layout`) на ширинах 114–260 и выйти; `-host`, `-symbol` и токен не нужны |

`-symbol` должны совпадать с `symbols` в `config.yaml` сборщика: иначе
соответствующая строка покажет «нет данных».

Интерфейс занимает терминал (alt-screen), поэтому логи пишутся в файл
`tui_client.log` в рабочей директории.

Клавиши: `q` или `Ctrl+C` — выход.

## Токен

Токен читается из переменной окружения `STATUS_TOKEN` или из файла
`.env` (в рабочей директории или рядом с бинарником). Он должен
совпадать с `STATUS_TOKEN` сборщика на VPS и используется для обоих
источников (статус-сервер и `sysagent`). Неверный токен статус-сервер
отклоняет закрытием соединения с кодом 4003.

```bash
cp .env.example .env
# отредактировать .env, вписать реальный токен
```

`.env` в git не попадает (см. `.gitignore`).

## Протокол

Клиент только читает и использует два независимых источника.

**Статус сборщика**: WebSocket `ws://{host}:{port}`. Первым сообщением
клиент шлёт `{"token": "..."}`, затем сервер присылает push-сообщения не
чаще раза в секунду:

```json
{
  "type": "status",
  "uptime_seconds": 1234.5,
  "total_disk_bytes": 987654321,
  "symbols": {
    "BTC_USDT": {"snapshots_since_start": 42, "last_snapshot_age_seconds": 0.3}
  }
}
```

При обрыве клиент автоматически переподключается (пауза 3 секунды).

**Метрики VPS**: HTTP `GET http://{host}:{sys-port}/sys` с заголовком
`Authorization: Bearer <токен>`. Опрос раз в 5 секунд, таймаут запроса
3 секунды. Ответ:

```json
{
  "cpu_percent": 12.5,
  "mem_total_bytes": 0, "mem_used_bytes": 0, "mem_used_percent": 41.0,
  "disk_total_bytes": 0, "disk_used_bytes": 0, "disk_free_bytes": 0,
  "disk_used_percent": 7.3
}
```

На графики идут `cpu_percent`, `mem_used_percent` и
`disk_used_percent`. Недоступность `sysagent` не влияет на статус
сборщика и наоборот.

## Раскладка (шапка и подвал)

Шапка и подвал описаны не в Go-коде, а в YAML: что рисовать, каким шрифтом, каким
цветом, где и при какой ширине терминала. Встроенное описание лежит в
[`internal/ui/default_layout.yaml`](internal/ui/default_layout.yaml)
(вшито в бинарник). Чтобы изменить вид без пересборки, скопируй образец и
запусти с `-layout`:

```bash
cp layout.example.yaml layout.yaml
# правишь layout.yaml
./tui-client -host <IP> -symbol BTC_USDT -layout layout.yaml
```

Внешний файл заменяет те зоны (`header`, `footer`), которые в нём
описаны; остальные остаются встроенными. Поэтому файл только с шапкой
работает как раньше, а подвал берётся из встроенной раскладки. Разбор
строгий: опечатка в ключе, типе, шрифте, размере, выравнивании или в
имени зоны, повтор зоны и пустой файл дают понятную ошибку при старте, а
не молчаливое игнорирование.

### Устройство

Зона состоит из одной строки `row`. Элементы строки раскладываются по
трём кластерам по свойству `align` (`left` по умолчанию, `center`,
`right`), свободное место делится между кластерами поровну. Элемент
может быть колонкой (`column`): вертикальный стек элементов с
собственным выравниванием по горизонтали. Вложенные колонки не
поддерживаются.

```yaml
layout:
  - zone: header
    row:
      - { type: banner, text: dtrader, font-size: lg, font-color: brand, bold: true }
      - align: right
        column:
          - { type: clock, bind: now_utc, font: digits, font-color: ok, bold: true, align: right }
          - { type: text, label: "UTC · снапшотов всего: ", bind: snapshots_total, font-color: data, margin-top: 1, align: right }
```

### Типы элементов

| `type`   | Что рисует                                                      | Обязательное |
|----------|-----------------------------------------------------------------|--------------|
| `banner` | FIGlet-текст                                                    | `text`       |
| `clock`  | часы: `font: digits` — семисегментные «ЧЧ:ММ» с мигающим двоеточием (`bind` — время RFC3339); иначе время из FIGlet-цифр с секундами (`bind` — строка вида `15:04:05`) | `bind`       |
| `text`   | обычная строка: подпись, значение, суффикс                      | `bind`       |
| —        | колонка: задаётся ключом `column` вместо `type`                 | `column`     |

### Свойства

| Свойство      | Для чего                | Значения и смысл                                                                              |
|---------------|-------------------------|------------------------------------------------------------------------------------------------|
| `text`        | `banner`                | что нарисовать                                                                                 |
| `bind`        | `clock`, `text`         | имя значения из данных приложения (см. ниже); нет такого имени — выводится `?`                 |
| `label`       | `text`                  | подпись перед значением                                                                        |
| `suffix`      | `text`                  | подпись после значения                                                                         |
| `font-size`   | `banner`, `clock`       | `sm` (small), `md` (standard), `lg` (banner3). По умолчанию: `banner` — standard, `clock` — small |
| `font`        | `banner`, `clock`       | явный FIGlet-шрифт из `banner.Fonts()` кита; приоритетнее `font-size`. У `clock` ещё `digits` — семисегментные цифры кита (3 строки, `font-size` игнорируется) |
| `font-color`  | любой                   | `brand`, `ok`, `data`, `muted`, `warn`, `sos` (палитра `theme`) или код цвета (`"214"`, `"#ff8800"`) |
| `label-color` | `text`                  | цвет `label` и `suffix`; по умолчанию `muted`                                                  |
| `bold`        | любой                   | жирность                                                                                       |
| `margin-top`  | любой                   | пустых строк над элементом                                                                     |
| `align`       | любой                   | `left`, `center`, `right`: в строке выбирает кластер, в колонке выравнивает по горизонтали     |
| `valign`      | элемент строки          | `top`, `center` (по умолчанию), `bottom`: по вертикали внутри строки                           |
| `show-from`   | любой                   | показывать при ширине терминала **не меньше** N колонок                                        |
| `show-until`  | любой                   | показывать при ширине терминала **не больше** N колонок                                        |

Цветовые имена берутся из `theme`, поэтому подчиняются `theme.yaml`, если
он есть.

### Данные

Приложение отдаёт зонам значения по именам (`bind`).

Шапка (`header`):

| Имя               | Значение                                              |
|-------------------|-------------------------------------------------------|
| `time_utc`        | текущее время UTC строкой, `15:04:05`                 |
| `now_utc`         | текущее время UTC в формате RFC3339 (для `clock` с `font: digits`) |
| `snapshots_total` | сумма `snapshots_since_start` по всем символам        |

Подвал (`footer`):

| Имя      | Значение                                                                                   |
|----------|--------------------------------------------------------------------------------------------|
| `status` | состояние подключения; приходит **уже окрашенным** (цвет зависит от состояния и выбирается в Go) |

Подсказка `q — выход` в подвале не данные, а `suffix` элемента в
раскладке: её текст и цвет (`label-color`, по умолчанию `muted`) меняются
в YAML.

### Встроенная раскладка и ширина терминала

Встроенная шапка адаптируется через `show-from` / `show-until`:

| Ширина терминала | Что в шапке                                                             |
|------------------|-------------------------------------------------------------------------|
| от 174           | логотип `dtrader` + подпись `history` + крупные часы и счётчик справа  |
| 125–173          | логотип + крупные часы и счётчик справа                                 |
| до 124           | логотип + однострочные время с секундами (по центру) и счётчик (справа) |

### Что важно знать

- Движок рисует зоны **`header` и `footer`**. Таблица и правая панель
  пока рисуются Go-кодом; зона с любым другим именем в `-layout` — ошибка.
- Высота подвала считается по факту отрисовки: длинный статус переносится
  на следующую строку, а тело при этом уменьшается, а не выталкивает
  экран за нижний край.
- Пороги `show-from` / `show-until` зависят от ширины выбранных
  шрифтов. Встроенные значения охраняет тест, а собственный `layout.yaml`
  проверяется режимом `-check-layout` (см. ниже): запусти его после
  каждой правки порогов или шрифтов.
- Встроенная раскладка рассчитана на терминал **от 114 колонок**: на
  меньших ширинах шапка при большом счётчике снапшотов (10 знаков) уже
  не помещается.
- Часы `font: digits` показывают часы и минуты без секунд; мигание
  двоеточия считается по времени, поэтому приложение обновляет экран
  каждые 500 мс. Секунды видны только в однострочной раскладке узкого
  терминала.
- Раскладка читается один раз при старте; чтобы увидеть правки,
  перезапусти клиент (пересборка не нужна).

## Проверка раскладки

```bash
./tui-client -check-layout                      # встроенная
./tui-client -check-layout -layout layout.yaml  # своя
```

Режим не запускает интерфейс и не подключается к сборщику. Он прогоняет
зоны `header` и `footer` по ширинам терминала 114–260 (счётчик снапшотов
считается 10-значным, статус подвала — «подключено · аптайм сборщика
9999999с») и для каждой зоны сообщает:

- **ок** и минимальный запас по ширине;
- **ОШИБКА**: содержимое не помещается в строку, перенесётся и сломает
  рамку; указаны диапазоны ширин и наибольшая нехватка. Код возврата 1;
- **ВНИМАНИЕ**: блоки стоят вплотную, промежутка между ними нет. Код
  возврата остаётся 0.

```
header: ОШИБКА — содержимое не помещается в строку и перенесётся:
  ширины 114–135: не хватает до 22 колонок
```

Лечится порогами `show-from` / `show-until` (спрятать лишний элемент на
узком терминале) или меньшим `font-size`. Длинное сообщение об ошибке в
подвале не проверяется: оно переносится на следующую строку штатно.

## Структура проекта

| Путь                          | Роль                                                                   |
|-------------------------------|------------------------------------------------------------------------|
| `main.go`                     | флаги, токен, загрузка `-layout`, запуск bubbletea                     |
| `internal/statusclient/`      | WebSocket-клиент статуса с автопереподключением                        |
| `internal/ui/model.go`        | главная раскладка (шапка / тело / подвал), таблица символов            |
| `internal/ui/layout.go`       | загрузка раскладки: вшитая `default_layout.yaml`, `-layout`, доступ к зонам |
| `internal/ui/header.go`       | шапка: вызов движка, данные `bind`                                     |
| `internal/ui/check.go`        | режим `-check-layout`: проверка зон по диапазону ширин                 |
| `internal/ui/default_layout.yaml` | встроенная раскладка (зоны `header` и `footer`)                    |
| `internal/ui/rightbar.go`     | правая панель: графики CPU/RAM/DISK (`sparkbar`)                       |
| `internal/ui/sysclient.go`    | HTTP-клиент `sysagent` (опрос раз в 5 с)                               |
| `internal/ui/footer.go`       | подвал: вызов движка, данные `bind` (статус подключения)               |
| `internal/dtui/`              | движок раскладки: `layout.go` (схема, строгий разбор), `render.go` (отрисовка зоны) |
| `layout.example.yaml`         | образец для `-layout`                                                  |

`internal/dtui` не импортирует код приложения: значения приходят по
именам (`bind`). Когда раскладку захочет второй проект, пакет
переносится как папка. Замысел и границы описаны в
[`ARCHITECTURE.md`](https://github.com/Dmitriy-495/dtui-kit/blob/main/ARCHITECTURE.md)
кита.
