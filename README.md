# dtrader-history-tui

Независимый TUI-клиент для мониторинга статуса сборщика
[`dtrader-history`](https://github.com/Dmitriy-495/dtrader-history)
(collector) по сети.

Не имеет прямого доступа к файлам или процессу сборщика — только к
тому, что WS-сервер статуса сборщика решил прислать по сети. Можно
запускать на любой машине, в любой сети, без SSH-доступа к VPS, на
котором крутится сам сборщик.

Переписан с Python (`textual` + `websockets`) на Go
(`bubbletea` + `gorilla/websocket`) по тем же причинам, что и
`dtrader-history`: один самодостаточный бинарник вместо venv/
интерпретатора.

## Установка

```bash
go build -o tui-client .
```

## Использование

```bash
./tui-client -host <IP-VPS-сборщика> \
  -symbol BTC_USDT -symbol SOL_USDT -symbol AVAX_USDT
```

Флаги:

| Флаг       | Обязателен | По умолчанию | Описание                                                    |
|------------|------------|--------------|--------------------------------------------------------------|
| `-host`    | да         | —            | IP или домен VPS, где крутится `collector`                   |
| `-port`    | нет        | `8765`       | Порт статус-сервера сборщика                                  |
| `-symbol`  | да (1+)    | —            | Символ для строки в таблице; указывается многократно          |

`-symbol` должны совпадать с `symbols` в `config.yaml` сборщика —
иначе соответствующая строка будет показывать «нет данных».

## Токен

Токен читается из переменной окружения `STATUS_TOKEN` (или файла
`.env` в рабочей директории/рядом с бинарником). Должен совпадать со
значением `STATUS_TOKEN`, которое использует `collector` на VPS —
иначе сервер отклонит подключение с кодом закрытия 4003.

```bash
cp .env.example .env
# отредактировать .env, вписать реальный токен
```

## Протокол

Клиент подключается по WS к `ws://{host}:{port}`, первым сообщением
шлёт `{"token": "..."}`, затем читает push-сообщения вида:

```json
{
  "type": "status",
  "uptime_seconds": 1234.5,
  "total_disk_bytes": 987654321,
  "symbols": {
    "BTC_USDT": {"snapshots_since_start": 42, "last_snapshot_age_seconds": 0.3}
  }
}
```

Сервер шлёт обновления не чаще раза в секунду. При обрыве соединения
клиент автоматически переподключается (пауза по умолчанию — 3
секунды).

## Интерфейс

- Заголовок и метаданные: аптайм сборщика, занятое место на диске
- Таблица по символам: количество снапшотов с момента запуска
  сборщика, возраст последней записи, статус («работает» /
  «ЗАСТРЯЛ?» — порог 5 секунд без новых данных)
- `q` — выход

## Разработка

```bash
go test ./... -race
```
